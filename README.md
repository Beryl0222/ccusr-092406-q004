# 非遗体验安全放行

本项目用于整理非遗体验安全放行领域中的事件名称、交换字段与脱敏样例，方便业务、运营和研发人员在同一套术语下讨论后续服务。资料只包含领域约定，不包含真实个人信息、生产连接或外部账号。

## 目录

- `src/heritage_workshop_safety.py`：事件种类与最小字段校验（领域契约）。
- `src/batch_release.py`：批次放行服务，把材料接收与工艺版本扩展为完整的场次放行流程。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/`：保证样例与领域约定一致，并覆盖批次放行全流程。

## 批次放行流程

- **登记**：工艺版本（年龄限制、所需教师资质、监护确认门槛）、材料批号（过敏提示、最低年龄）、工具状态、教师资质。
- **排场**：每场体验锁定工艺版本、材料批号、工具、教师与名额；系统即时给出风险建议（阻断项与提醒项）。
- **复核**：安全、工艺、运营三类角色全部复核通过且无阻断项后，场次才放行（`BATCH_RELEASED`），此前不能签到。
- **确认与签到**：家庭监护确认幂等占用名额，重复提交不产生第二份资格；签到按场次放行状态与最新年龄限制校验，重复签到返回同一记录。
- **冻结**：材料召回、设备失效、教师资质变化或现场事件只冻结受影响的未完结场次，并只下发一次停用通知；工具或资质恢复后自动解除对应冻结。已经完成的体验保留当时依据，不再受冻结影响。
- **替换**：替换材料会作废旧复核、重新计算年龄与过敏限制，需重新复核后才可放行，不能沿用旧签署。
- **隔离**：同一批号再次接收内容冲突时批号被隔离，原始记录不被覆盖，使用中的未完结场次被冻结。
- **恢复**：全部状态由事件日志投影而来，进程中断后重放日志即可继续未完成的复核与通知，既不重复占用名额，也不重复下发停用消息。
- **追溯**：任一参与记录可追到实际工艺版本、材料批号、工具状态、教师与放行复核人。

## 本地核对

```bash
python3 -m unittest discover -s tests
```

## 本地运行

测试命令：

```bash
python3 -m unittest discover -s tests
```

编译或构建命令：

```bash
python3 -m compileall -q .
```

所有测试和构建均在单个 Linux 应用容器内完成，不需要另行启动数据库或外部服务。
