# 非遗体验安全放行

本项目把非遗亲子体验的**材料接收与工艺版本**扩展为一套**批次放行流程**：
每场体验在开课前锁定实际依据，系统先给风险建议，不同角色复核齐备后才允许签到；
材料召回、设备失效、教师资质变化或现场事件只冻结真正受影响的场次与批次。

全部状态以 append-only 事件日志为唯一事实来源，不依赖数据库或外部服务，
所有核对都在单个 Linux 容器内完成。资料只包含领域约定与虚构数据。

## 放行流程

```
工艺版本登记 / 材料批号接收 / 工具校准 / 教师资质 / 场次排期
                          │
                          ▼
              场次锁定六要素（SESSION_LOCKED）
   工艺版本 · 材料批号 · 工具状态 · 教师资质 · 年龄限制 · 监护确认
                          │ 系统即时产出风险建议（BLOCK/WARN/INFO）
                          ▼
   参与者报名（占名额，幂等）+ 监护确认（针对锁定依据签署，幂等）
                          ▼
        多角色复核（SAFETY_OFFICER + OPERATIONS_MANAGER）
                          ▼
                     放行（记录放行人）
                          ▼
                     参与者签到
                          ▫
                      场次完成 → 当时依据永久封存
```

关键规则：

- **风险建议先行，复核后放行**：年龄超限、过敏原命中、缺少监护确认、
  教师资质级别不足/过期、批号未接收/召回/隔离、工具失准等均为 BLOCK；
  任一 BLOCK 存在或复核角色不齐/被拒，都不能放行，更不能签到。
- **冻结精准传播**：材料召回/隔离、设备停用、教师资质撤销只冻结
  **当前锁定依据命中且未完成**的场次；未使用该批号/工具的场次不受影响。
  已完成场次保留当时快照依据，事后召回不追溯、不改写。
- **替换材料必须重算**：`MATERIAL_SWAPPED` 会作废旧锁（`LOCK_SUPERSEDED`）、
  旧复核（`REVIEWS_VOIDED`）与旧监护签署（确认绑定 lock_id，自动失效）；
  名额与报名保留，须按新批号重新锁定、重新签署、重新复核，不能沿用旧放行。
- **幂等与隔离**：家庭重复提交确认/重复报名不产生第二份资格、不重复占名额；
  同一 `event_id` 内容一致的重放被忽略，内容冲突直接拒绝；
  同一批号接收到冲突内容时自动 `BATCH_QUARANTINED` 整批隔离。
- **中断续做**：冻结、作废、隔离、通知请求都是由 `ReleaseService.pump()`
  从日志确定性派生的事件（id 由原因生成）。进程中断后重放日志重跑 pump
  即可补齐；停用/冻结通知经发件箱按幂等键下发，通道“已发送未确认”时
  重跑只取回原回执，不会重复下发。
- **全程可追溯**：`trace(participant_id, session_id)` 可从任一参与记录
  追到实际工艺版本、各材料批号、工具与教师状态、年龄规则、监护确认版本、
  风险建议、复核角色与放行人；签到后即使依据后来作废，也按签到当时快照呈现。

## 目录

- `src/events.py`：事件种类、最小字段校验、JSONL 事件日志（原子写、按 `event_id` 幂等/冲突拒绝）。
- `src/release.py`：日志折叠投影、风险评估、锁定/复核/放行/签到门禁、
  冻结与作废的确定性派生（`pump`）、换料、追溯查询。
- `src/notifications.py`：通知发件箱与中继，`RecordingSink`/`FlakySink`
  模拟幂等消息通道及“发送后崩溃”。
- `src/heritage_workshop_safety.py`：基线模块的兼容入口，再导出事件约定。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/test_contract.py`：样例与领域契约一致性。
- `tests/test_release_flow.py`：放行全流程与边界场景（27 个用例）。
